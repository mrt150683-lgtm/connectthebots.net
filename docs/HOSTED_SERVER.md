# Hosted server: accounts, reports, interactions and notifications

30 October 2026. `connectthebots_server` is separate from the frozen R0 and fictional local runtimes. Foundation/accounts, report and board milestones have local verification records. The current candidate adds a configured security-contact endpoint to accounts, reports, postings, mutual-consent conversations, notifications, exact-target concern reports, CLI-only operator controls and guarded backup/recovery. Account access remains disabled by default; production is unchanged. Real email delivery and operational readiness remain unfinished. ## Run and test

Use Python 3.12 on Ubuntu 24.04 for staging/production. Windows development also works. Install `requirements-server.lock` with `python -m pip install --require-hashes --only-binary=:all: -r requirements-server.lock`. The `server` extra exactly pins Starlette, Uvicorn, httpx, PyJWT with cryptography, cryptography itself and Jinja2. The lock includes transitive dependencies and wheel SHA-256 values. These supply routing, HTTP, token verification and escaped HTML; no ORM, model or account SDK is used. The fictional runtime's cryptography pin is aligned at `50.0.2` and its 263-test regression suite passes.

Set environment variables using `site/deploy/app.env.example` as a guide, with an absolute disposable `DATABASE_PATH` and a generated `SESSION_SECRET`; never commit a filled environment file. The application does not load dotenv files. From an installed wheel, run `python -m connectthebots_server`. A source checkout additionally needs `PYTHONPATH=src`. The process binds only `127.0.0.1:8100`, uses one worker, and does not log request URLs or bodies.

Run `PYTHONPATH=src python -m unittest discover -s tests_server -v` (PowerShell: `$env:PYTHONPATH='src'`). HTTP/auth tests skip when optional dependencies are absent; database/configuration tests remain standard-library-only. These tests are separate from packaged R0 self-tests. With server dependencies and Playwright available, `node site/tools/check_auth.mjs --out artifacts/auth-browser` runs desktop/mobile account journeys against a test-only local RSA identity provider. Set `PYTHON` and `PLAYWRIGHT_MODULE` if needed. The test provider cannot be enabled through production environment configuration.

## Implemented behavior

- Startup enables SQLite WAL and foreign keys, checks migration history against packaged SQL hashes, then applies missing migrations in one transaction. Failed SQL rolls back schema and history. Unknown, edited or out-of-order history prevents startup. UTC time is injected.
- `/healthz` returns only `{"status":"ok"}` with 200 when the database is reachable and migration history matches, or `{"status":"unavailable"}` with 503. It never recreates a missing database during a health read.
- `/.well-known/security.txt` returns configured role-contact metadata over HTTPS with a fixed review expiry. It needs no account, cookie or database. Missing/stale configuration yields a generic 503 without disabling other routes; see configuration below.
- `ACCOUNT_SIGNIN_ENABLED=false` leaves `/app` and `/signin` as honest 503 preparation pages. Enabled accounts require Google client credentials. Production additionally requires approved legal pages and complete controller, contact, provider and transfer settings. A configuration flag is not deployment approval.
- Google authorization code and PKCE use ten-minute single-use browser-bound state and nonce, fixed Google endpoints, RS256 token checks and bounded JWKS caching. Google `sub` identifies an account; email changes do not create another account. Google access/refresh tokens are not retained.
- Random session tokens are stored only as hashes. `__Host-` cookies are Secure, HttpOnly and SameSite=Lax. Sessions rotate on sign-in, slide up to 30 days of activity with a 90-day absolute limit, and are revoked on logout or deletion. Writes require the current session's CSRF token and a same-origin request.
- Signup modes are `open`, `invite` and `closed`; the default is closed. Invites are hashed and single use. Closed signup still admits existing accounts. The waitlist requires explicit consent and has a removal code; duplicate submissions do not replace the original removal authority. Auth routes share a bounded per-IP limit of 20 requests per minute with `Retry-After`.
- `/app` derives seven states from actual reports and owner preferences. Key creation alone stays setup. Pausing stops new website intake, not the assistant; missed reports require an explicit cadence plus six hours' grace. Review does not imply consent to an introduction.
- `/app/keys` creates up to three active named keys, showing the full key/private prompt once, with rename/revoke and last-use metadata. `/api/v1/reports` is bearer-only, strict JSON, capped at 32 KiB, with transactional exact-body idempotency and durable 10/minute and 60/24-hour limits. `/api/v1/me` returns limited account connection metadata and only the owner's currently approved visible posting, never email, drafts or reports.
- `/app/reports/paste` validates then previews without a report write. Owner/purpose/expiry-bound signed confirmation plus CSRF is required to save; repeated confirmation returns the same stored result. All content is escaped, with HTTPS-only links and no Markdown rendering.
- `/app/posting` saves private revisions and shows the exact text/tags/looking-for/offering before explicit publication. Signed ten-minute approval binds owner, revision and hash; newer drafts or withdrawal invalidate it. `/board`, `/board.json` and per-post HTML/JSON expose only approved fields. Unpublish is immediate; anonymous JSON requests have a 120-token burst bucket refilling at two per second with hashed keys and a 4,096-entry cap.
- `/app/introductions` previews the exact two posting versions, note and reason before sending. A signed owner/purpose/expiry token and transactional current-grant checks bind the request; the recipient's separate Yes binds the same context before one conversation opens. Requests expire after fourteen days, with five pending outgoing and twenty new requests per seven days. Incoming requests appear on the dashboard.
- `/app/conversations` exposes participant-only plain-text messages, paginated history, explicit send and leave/block. Message retries use hashed nonces and exact body hashes. The limit is one hundred new messages per person per 24 hours. Blocking closes contact and filters both signed-in board views; anonymous public postings remain readable. Report keys never authorize human decisions or message access.
- `/app/account` exports profile, key metadata, reports/settings, posting drafts/versions/grants, introduction/conversation records, the owner's retained authored context, own messages, own block choices, notification preferences and event/delivery metadata, excluding secrets, unsubscribe capabilities, raw queued mail and peer message bodies. Confirmed deletion removes owner data and public slug, clears shared introduction context, closes threads and replaces the sender's messages with `[deleted]`. The other participant retains their own closed-thread history; both-owner deletion removes shared rows. A separate date-only receipt remains. Anonymous waitlist requests use their separate removal code.
- `/app/notifications` provides owner-only paginated history and explicit read actions; the bell is independent of email opt-in. `/app/notifications/preferences` has six native controls, optional types off and first-sign-in security on. Weekly in-app summaries show actual counts for a fixed seven-day period for all active accounts.
- `/email/unsubscribe/<token>` is a type-bound signed capability: GET/HEAD only confirm; a strict 1 KiB RFC 8058 POST stops that type without cookies, account selectors or redirects. Other mutations retain normal CSRF/Origin checks. Explicit foreign origins are still rejected globally.
- A bounded worker queues generic mail, batches conversation alerts hourly and rechecks current authority and preference before hand-off. Default outbox mode never opens transport and its records are not replayed on SMTP activation. Production SMTP requires credentials and mandatory verified TLS; uncertain hand-offs are never automatically retried.
- `/app/report` binds the current owner and exact accessible posting/conversation context into a ten-minute signed form, with CSRF and current authority checked again at submission. Concern reports have six reasons, up to 2,000 plain-text characters, stable exact replay and a ten-per-day allowance. Only the operator CLI can list or inspect reports; no administrator HTTP routes are added.
- `/privacy`, `/terms` and `/contact` are unapproved review drafts for the current release. Rendered email wording reflects the configured mode; no actual provider delivery is claimed by local tests.
- Requests are bounded before route effects: 32 KiB on `/api/`, 64 KiB elsewhere, including streamed bodies. Unexpected hosts, cross-site write origins and encoded bodies are rejected. Errors omit exception/request contents. Responses are non-cacheable with strict CSP and security headers. No administrator, debug or schema web routes are exposed.

## Security contact configuration

Before publishing `/.well-known/security.txt`, verify that the role mailbox in `CONTACT_EMAIL` receives mail. Set `SECURITY_CONTACT_EXPIRES` in the protected environment to a fixed UTC timestamp in `YYYY-MM-DDTHH:MM:SSZ` format, later than the current time and at most 365 days ahead. Review the mailbox and renew this timestamp before expiry; requests, restarts and installation never renew it automatically. These values are operational configuration, not source-code defaults, and no personal name is included in the response. An absent/invalid mailbox, missing/expired expiry, expiry more than 365 days ahead, or non-HTTPS configured/request scheme produces HTTP 503. Invalid expiry syntax or an impossible calendar date is refused during configuration.

The unsigned [RFC 9116](https://www.rfc-editor.org/rfc/rfc9116.html) response is UTF-8 `text/plain` with URI-encoded `Contact`, one `Expires`, a `Canonical` URL derived from `PUBLIC_BASE_URL`, and `Preferred-Languages: en`. It advertises no encryption key. The exact nginx location forwards only this well-known path; the normal boundary applies `no-store` and security headers. Uvicorn trusts forwarded scheme/client headers only from its loopback proxy, and nginx replaces those headers with the observed scheme/client. That wiring does not establish public certificate validity or mailbox delivery. HTTP-only local staging correctly returns 503; public HTTPS and actual receipt remain launch acceptance checks.

## Release artifacts and staging

Build with the pinned build tools: `python -m pip wheel --no-index --no-deps --no-build-isolation . --wheel-dir artifacts/server-dist`. Package using `python tools/build_server_bundle.py --wheel artifacts/server-dist/agentmatch-0.1.0-py3-none-any.whl --out artifacts/server-bundle`. The bundle holds `site/` plus `app/` containing the wheel, dependency lock and SHA-256 manifest. It contains no checkout or environment file.

Deploy scripts preserve static-only operation. Add `--with-app --wheel <wheel>` or `-WithApp -Wheel <wheel>` for the application. Preview using `--dry-run` or `-DryRun`. HTTP staging requires explicit `--environment staging --skip-tls` or `-Environment staging -SkipTls`. Production requires HTTPS. Setup creates disabled, closed accounts and outbox-only email. Secure cookies require HTTPS for public staging; the local browser fixture uses localhost.

On a clean, disposable Ubuntu 24.04 system, `sudo python3 tools/verify_server_staging.py --bundle <absolute bundle> --out <absolute evidence directory>` installs and checks the bundle. It refuses unrelated pre-existing paths. `--reuse-staging` permits a checked upgrade of the same disposable staging installation; `--verify-only` additionally skips installation. It does not modify SSH or enable the firewall. Run `site/tools/check_server.mjs --base-url http://localhost` and `site/tools/check_site.mjs --base-url http://localhost` for installed-route/browser evidence; the override accepts loopback only. See [real Google setup](GOOGLE_SIGNIN_SETUP.md).

Installation creates the `ctb` account without a login shell, a root-owned `0600` environment file, a writable service data directory and an immutable release-specific virtual environment. Dependencies require hashes; the application wheel installs without dependency resolution. `/opt/connectthebots/venv` points to the selected release. The HTTP and notification units limit writes to `/var/lib/connectthebots`. The network-isolated nightly backup unit also writes to the private `/var/backups/connectthebots` directory; the weekly certificate unit has only the application-data write path and skips its network check on HTTP staging. The separate hardened `connectthebots-notifications.service` runs a bounded `python -m connectthebots_server.notifications tick --limit 20`; its timer starts after two minutes and runs about one minute after each completed tick. It uses the same protected environment and writable data directory. nginx proxies dynamic paths, redirects hosted `/signin.html` to `/signin`, keeps `/example` for the labelled static dashboard and redirects www to the canonical hostname. Nginx has a 64 KiB request cap; the app applies its tighter API limit.
