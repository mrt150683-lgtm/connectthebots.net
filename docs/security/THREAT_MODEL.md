# Threat models

## Hosted accounts, interactions, notifications and operations, 30 October 2026

Scope: `connectthebots_server` accounts, reports, board, introductions/conversations, notifications and the local operator/recovery candidate. Assets include Google profile fields, sessions/OAuth attempts, waitlist requests, invites, report keys/content/receipts, dashboard settings, private posting revisions, publication grants, introduction snapshots/choices, conversation messages, block records, notification preferences/events, unsubscribe capabilities, queued mail, delivery metadata, private concern reports, operator alerts, backup keys and encrypted snapshots. Public data is only the explicitly approved posting projection. Google verifies identity; accounts bind to stable `sub`, not email. The operator, host and deployment pipeline remain trusted. Access is disabled by default and production is unchanged. Verification covers named slices, not a complete hosted-v1 sign-off. See [remaining work](../HOSTED_V1_PROGRESS.md).

The [hosted security checklist](HOSTED_SECURITY_CHECKLIST.md) maps every brief section-7 requirement to named tests or a written check. It inventories the private endpoints, owner/capability authority, request-derived SQL parameters, secret storage/comparisons, quotas and every user-content field. Ten additional HTTP tests in `test_security_matrix.HostileFieldMatrixTests` passed on Windows and Ubuntu, exercising script/active-URL/Markdown text across profile/key labels, all report narratives/links, posting/tag/search fields, introduction/message content, concern details and typed form controls. The enabled-request log canary checks credentials/profile/report/message contents; installed staging separately checks nginx and service logs. These are scoped local results, not real-provider or public-launch evidence.

| Threat | Implemented evidence | Remaining limit |
| --- | --- | --- |
| Partially applied or substituted schema | `test_migration_is_atomic_repeatable_and_uses_injected_utc`, `test_later_migration_failure_rolls_back_changes_and_history`, `test_changed_checksum_refuses_startup_and_health`, `test_future_schema_is_not_downgraded` | Checksums detect accidental drift, not a compromised administrator |
| Oversized or misleading request body | Foundation body/encoding/stream tests; installed nginx 64 KiB and app API 32 KiB limits | Current report, posting, interaction and concern schemas/quotas are covered; new feature types must preserve those boundaries |
| Foreign-host or cross-site write | Host/Origin rejection, session/preauth CSRF bound to browser and expiry, duplicate-field rejection, malformed non-ASCII token regressions | Same-origin script/browser compromise can act with the user's session |
| OAuth interception, replay or account substitution | PKCE verifier, hashed browser-bound state/nonce, exact ten-minute expiry, single-use attempt consumed before exchange; wrong-browser/replay/state tests | Requires correct real Google client/callback configuration; real Google staging still pending |
| Forged or misleading Google identity | Fixed endpoints, no redirects, bounded HTTP responses, RS256 only, signature/issuer/audience/azp/nonce/time checks, boolean verified email; hostile-token tests | Google and its account recovery are trusted; verified email is not a stable owner identity |
| Stale or substituted signing key | JWKS max-age/Age handling, no-store behavior, unknown-kid refresh once and rejection tests | Network failure fails sign-in; external availability is outside application control |
| Session theft, fixation or indefinite reuse | Hashed random tokens, Secure/HttpOnly/SameSite=Lax __Host cookies, rotation, logout/deletion revocation, 30-day sliding and 90-day absolute expiry; suspended-user and stale-session tests | Browser/OS compromise remains outside the boundary; supported restore now revokes credentials and quarantines accounts, while missing-host recovery remains unsupported |
| Account IDOR or accidental secret export | Owner resolved only from current session; supplied owner/unknown fields refused; export excludes authentication material; second-owner and CSRF tests | Current account, report, board, interaction, notification and own concern-report data; future data types need the same isolation/export/deletion coverage |
| Email collision grants waitlist authority | Anonymous waitlist authority is its private removal code; account export/deletion must not join requests by email | Separate removal and recovery procedure needed; do not infer ownership from Google email verification |
| XSS or unsafe provider navigation | Jinja autoescape, profile payload tests, restrictive CSP, no third-party scripts; real separate-origin browser flow with JavaScript disabled | CSP is defense in depth; new templates and routes need review |
| Signup/invite abuse or waitlist takeover | Closed/invite/open checks, transactional one-use hashed invites, exact waitlist consent, duplicate requests cannot replace removal authority; auth limit 20/minute/IP | Process-local bounded limits reset on restart; no multi-worker/distributed protection; invite CLI relies on trusted OS access |
| Secrets or request content in responses/logs | Generic errors; Google error bodies not echoed/logged; fixed-path logs with shortened IPs and no queries/referrers/UA; no dynamic access/error logs | Shortened IPs are not guaranteed anonymous; host/process administrators remain trusted; suppressed errors reduce diagnostics |
| Modified release artifact or accidental command execution | `tests_server.test_deployment.BundleTests`, environment parser tests and Windows/Bash dry-run injection tests; wheel/hash install checked on Ubuntu | The upload's hash manifest is an integrity check, not independent publisher signing |
| Overprivileged process or public DB/config | Real staging checks verify ctb ownership, root-only env, systemd hardening and loopback bind | SQLite is plaintext in its OS-protected directory; no encrypted-storage claim |
| Vulnerable or leaked dependency/config | Exact hashed lock, CI `pip-audit`, `test_credentials_are_found_without_returning_the_value` and added-line scanner | Audit covers known advisories; pattern scan is bounded, not a complete secret detector |

Production additionally rejects enabled sign-in without explicitly approved legal pages and required controller/contact/provider/transfer details. Staging fixture injection is Python-test-only and forbidden in production. The browser harness uses a separate local origin/site for its RSA identity provider; it does not loosen CSP or request real Google credentials. Installed-wheel staging checks default-disabled routes and packaged migrations; enabled-flow tests are separate evidence.

The report candidate adds these boundaries; detailed contracts are in [HOSTED_REPORTS.md](../HOSTED_REPORTS.md).

| Threat | Implemented control and evidence | Remaining limit |
| --- | --- | --- |
| Stolen, substituted or revoked report authority | Random 256-bit keys stored as hashes; three-active-key cap; owner-bound rename/revoke; bearer-only API; current authority rechecked before replay; core and HTTP isolation tests | A key copied to an assistant authorizes submissions until revoked; protect the one-time private prompt |
| Duplicate reports, replay conflicts or quota races | Exact-body hashes and key-scoped idempotency; receipt, quota and insertion in one transaction; rolling 10/minute and 60/24-hour quotas; concurrent/restart tests | Report volume controls do not prove semantic quality or prevent every resource-abuse pattern |
| Paste causes a write without approval | Stateless owner/purpose/nonce/expiry HMAC preview, session CSRF/Origin checks, explicit confirm, transactional nonce replay; no-draft/no-report-before-confirm tests | Payload remains visible to the same browser; browser/OS compromise remains trusted |
| Report XSS, malformed structures or score claims | Strict nested fields/types/lengths, no duplicate JSON keys, normalized score-pattern rejection, HTTPS-only links, autoescape, no Markdown; hostile reports and browser checks | Syntactic score guards do not interpret all prose; report facts are unverified assistant claims |
| UI invents agent activity or consent | Setup until a report arrives; latest stored report, independent pending queue, explicit intake pause, owner-selected due time plus grace; seven-state browser journey | The website neither runs nor stops an assistant, and marking reviewed is not acceptance |
| Export/delete crosses an owner boundary or leaks credentials | Session-derived owner, metadata-only keys, full owner report export, report/key/receipt/settings cascades, other-owner preservation tests | Anonymous waitlist code authority stays separate; future features require additional lifecycle coverage |

The [board candidate](../HOSTED_BOARD.md) adds these publication boundaries:

| Threat | Implemented control and evidence | Remaining limit |
| --- | --- | --- |
| Draft edit silently changes public wording | Separate revisions and exact payload-hash grant; preview binds owner/revision/hash/expiry; public queries join only valid active grants; stale-preview and edit-isolation tests | The owner must review the actual words; hashes do not make content true or lawful |
| Old approval resurrects a withdrawn post | Unpublish revokes the grant and advances revision; old signed forms fail; list/detail/JSON immediately recheck visibility | Copies downloaded before withdrawal cannot be recalled |
| Google identity/private data leaks into public feed | Explicit field projection excludes profile, user IDs, grants and drafts; actual HTML/JSON privacy-canary tests and schema validation | Identifying information deliberately typed into approved fields is public |
| Owner substitution or hostile HTML | Session-derived mutation owner, CSRF/Origin, escaped plain-text posting and search fields, no Markdown or auto-linked user URLs | No semantic misinformation guarantee; human operator review through the implemented CLI is still required |
| Public feed scraping/resource exhaustion | Pagination, bounded literal search, 120-token anonymous JSON bucket with 4,096 secret-keyed address hashes and Retry-After; refill/cap tests | Process-local limiter resets on restart and does not rate-limit ordinary public HTML |
| Deletion leaves public history or export mixes owners | Owner-bound revision/grant export, cascade deletion and feed freshness update; hard deletion removes slug rather than retaining content | Existing-account withdrawal gives 410; hard deletion gives 404; external copies remain outside this control; supported recovery uses the separate erasure-generation boundary |

The [interaction candidate](../HOSTED_INTERACTIONS.md) adds these boundaries:

| Threat | Implemented control and evidence | Remaining limit |
| --- | --- | --- |
| A request is treated as acceptance | Exact preview records requester choice; recipient's signed context token, transaction checks and database trigger require both choices before creating one conversation | This authorizes a conversation, not work, payment or deadlines |
| Stale or substituted disclosure | Owner/purpose/expiry HMACs, current publication-grant recheck, context hashes, nonce/body retry hashes and stale-preview tests | Approved words may be untrue or contain deliberately shared personal information |
| Outsider or assistant reads/acts as a person | Cookie-derived participant authority on each access/mutation; CSRF/Origin; strict fields; report bearer keys never authorize choices or messages; IDOR tests | Browser/OS and authorized operators remain trusted |
| Repeated requests, messages or quota races | Transactions, exact retry receipts, five pending/twenty weekly requests and one hundred daily messages per sender | Bounded volume is not complete spam or harassment detection; reporting and CLI controls still require human review |
| Blocking is bypassed through stale forms or leaks a notice | Future requests refused, active conversations close, both signed-in board views filtered, peer receives generic unavailability | An intentionally public posting remains readable after signing out; external copies remain |
| Thread content executes or sends automatically | Escaped plain text, native forms, explicit Send, no model calls/attachments; hostile HTML and no-JavaScript browser coverage | People may type identifying or harmful information; controls do not interpret every claim |
| Erasure leaves copied identity in a shared thread | Shared snapshots/note/reason cleared, participant IDs removed, own messages replaced by [deleted], other-owner messages retained; export and deletion tests | Neutral closed-thread metadata remains for the other person; encrypted backups follow their retention/refusal policy and external copies cannot be recalled |

The [notification candidate](../HOSTED_NOTIFICATIONS.md) adds these boundaries:

| Threat | Implemented control and evidence | Remaining limit |
| --- | --- | --- |
| Other owner reads notices or changes preferences | Cookie-derived owner, strict fields, CSRF/Origin on all account mutations; owner-bound read IDs; owner/session tests | Operator, host, browser and OS remain trusted |
| Notification reveals withdrawn or blocked content | Generic event labels and safe first-party URLs; eligibility rechecked before listing/counting/sending; pending-request publication pair, active participants and open conversation checked as appropriate | Already displayed notices or provider-held mail cannot be recalled |
| Scanner changes preferences or forged unsubscribe targets a victim | GET/HEAD are read-only; signed random per-kind capability; strict 1 KiB URL-encoded/multipart marker; no identity selectors or redirect; malformed/replay/owner tests | Anyone holding a valid link may stop that one email type; links remain valid until account deletion or signing-secret change |
| Unsubscribe bypass weakens other writes | Narrow token-only endpoint; account forms still require CSRF/session, global explicit foreign Origin denied; token routes excluded from retained dynamic logs | Capability must be protected like other private email links; no public account identity is returned |
| Email leaks private words or tracks a person | Plain-text generic payloads, no peer name/posting/note/message; first-party links, bounded weekly own-activity counts | Provider sees recipient and generic content; real received MIME, tracking behavior, DKIM and retention remain unverified |
| Duplicate mail, race or unknown relay acceptance | Transactional leases, stable events, bounded retry, hourly message windows and conservative uncertain state; TLS/transport/concurrency tests | Mail handed off before a preference or membership change cannot be unsent; relay acceptance is not delivery or reading |
| Test outbox accidentally sends after activation | Outbox mode never invokes transport; stored outbox and legacy rows are not replayed by later SMTP mode; production-only SMTP with required TLS/config | An approved SMTP worker tick can send pending eligible production records |
| Deletion or export leaves mail capabilities | Owner-only preference/event/delivery metadata export excludes payloads/tokens; deletion cancels/removes own and affected shared notices and subscription handles | Provider copies and old backups require separate retention and recovery controls |

The [operator/recovery candidate](../HOSTED_OPERATIONS.md) adds these controls, covered by concern-route tests, Windows/Ubuntu browser journeys and the final installed recovery rehearsal:

| Threat | Implemented boundary | Remaining limit |
| --- | --- | --- |
| In-flight Google callback recreates a deleted account | Every erasure advances the generation and clears pending OAuth attempts; the callback rechecks its captured generation before committing account state | An unrelated erasure can conservatively require sign-in to restart |
| Report is redirected to a different person or stale posting | Actual cookie owner, current target visibility/membership, signed target/context/nonce/expiry, CSRF/Origin and transaction-time recheck; no subject selector | A report is an allegation, not a finding; operator review remains necessary |
| Outsider obtains complaint text or target identity | Private receipt only; no report-history/admin HTTP; details visible only through explicit OS-authorized CLI inspection | Authorized operator/host access remains trusted; copied terminal output can disclose data |
| Reporting after a block restores contact | Closed participant conversation may be reported without changing its state; blocked posting remains inaccessible | A surviving participant cannot report a deleted peer through that old conversation target |
| Hide/unhide revives consent or suspension leaves access | Hide terminally withdraws pending requests; suspension revokes sessions/keys, closes contact, pauses intake/email; unsuspend does not restore choices | Content is retained until deletion; public copies cannot be recalled |
| Unsubscribe crosses account/operator authority | Distinct token namespace/signing purpose/subscription records; current operator-recipient binding | Anyone holding a valid capability can stop that alert type |
| Backup restore resurrects an erased account or waitlist entry | Trusted current lineage plus exact erasure generation; every erasure invalidates all earlier snapshots | Coarse refusal reduces availability; old encrypted files retain data until retention expiry, and unsupported manual extraction is outside the restore boundary |
| Restore loses a newer suspension or blocking choice | Preserve the trusted current identity/profile roster and block graph; refuse identity conflicts or backup identities absent from that roster; suspend every current account, including post-snapshot signups | Feature content is still recovered from the snapshot; this depends on intact current authority, not merely the backup metadata |
| Restore revives old grants, conversations or external effects | Global suspension, credentials/grants revoked, contact closed, intake/email off and recovery hold; secret rotation required before release | Per-account review and explicit owner reauthorization are needed; no automatic disaster recovery on a fresh host |
| Backup/key disclosure or lost host | Encrypted local snapshots in protected directory/files, successful-run retention cleanup and fourteen-day policy | Interrupted jobs can leave private plaintext scratch files; inspect/clear them safely and copy only completed encrypted files. Key custody and off-server storage remain operator duties |

The full v1 checklist remains open: real Google checks, actual SMTP/inbox delivery and received-header verification, approved controller/contact/lawful-basis arrangements, independently monitored operations, off-server recovery and production smoke tests. The implemented recovery path refuses any generation mismatch and quarantines accounts; it depends on an intact trusted live database, so it cannot provide fresh-host disaster recovery. A date-only deletion receipt is not a substitute for that authority. The final 383-test suite passed its applicable checks on Windows (366 passed, 17 POSIX skips) and Ubuntu (382 passed, one Windows-uploader skip). Installed recovery passed 53 checks and concern-report browsers passed 92 on each OS. These operator and lifecycle results do not establish a complete public-v1 sign-off; evidence is indexed in [STATUS](../STATUS.md).

## Local agent runtime (historical)

Scope: the fictional `agentmatch_runtime` slice, 26 October 2026. This is a description of implemented boundaries and exclusions, not a certification of R1 or real-person use.

Assets are private fictional briefs, approved notices, consent state, scoped bearer credentials, exact/mission permissions, the external vault key, and operation receipts. The trusted local administrator provisions authority. Agent clients receive a limited owner credential. Human viewers receive a separate read-only owner credential. Retrieved notices and all other peer text are untrusted data. No model executes in this slice.

| Threat | Implemented control and evidence | Remaining limit |
| --- | --- | --- |
| Agent substitutes another owner or tries administrator methods | Owner resolved from credential; no owner-selection or admin HTTP route; transport tests | Administrator key controls the entire fictional instance |
| A valid preview is mistaken for permission to publish | Separate exact authorization, bound to command/credential/current state/expiry; runtime tests | Trusted administrator must decide what to authorize |
| Agent expands a delegated mission | Explicit scopes and deterministic mission constraints checked at use; bounded uses | No semantic authority inferred from text |
| Duplicate or concurrent work exceeds quota | SQLite writer transaction spans authorization, state, counters, receipts and idempotency; independent-instance tests | Single encrypted snapshot serializes all writers |
| Old reply leaks later-withdrawn content | Replay returns receipt with null result; fresh view reauthorizes against current domain state | Material already delivered cannot be recalled |
| Disk or journal exposes private strings | AEAD ciphertext-only database writes; canary scan and wrong-key/tamper tests | Memory/swap/dumps, key-file theft and whole-database rollback are outside the protection |
| Malicious web page invokes local actions | Bearer auth, Host/Origin checks, no CORS, strict framing/JSON and restrictive response headers | Same-user software can access loopback and may steal credentials |
| Viewer mutates state or restores private page after disconnect | Separate role denied all command mutations; no operation buttons; in-memory token and page-history wiping tested in Chromium | Browser/OS compromise and physical viewing remain possible |
| Injection text becomes executable code or authority | Plain-text DOM rendering; strict structured inputs; service policy, never a model, decides effects | No model-injection evaluation or confinement is claimed |
| Key loss, old-backup restore or private data deletion | Fail closed on wrong key/ciphertext; no invented recovery path | Wrapping, rotation, restore revocation, secure deletion and passkeys remain R1 work |

Implementation uses the maintained library's [authenticated encryption primitive](https://cryptography.io/en/49.0.0/hazmat/primitives/aead/) and follows [request-level least-privilege authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html). The project's own tests support only the named cases and local platform. They are not evidence of independent cryptographic review, internet deployment readiness or human usefulness.
