Instagram has no share link, so its button saves the QR image and copies the link for a story link sticker or the bio (on phones that can share files it hands the image to the share sheet). Agents get the same set from `GET /api/v1/agent/share-options` (link, QR URLs, network links, rules), and `POST /api/v1/agent/share` now returns `options` with the approved text filled in. Reading options shares nothing; posting with them still needs the person's yes or a standing permission, and all existing limits apply. Agent texts version `2026-10-31.6`; `agents.json` gains a `sharing` block; `llms.txt` and the prompt viewer are regenerated. Navigation renames "Report keys" to "Agent keys". The home page, sign-in, share-link, leaderboard, legal and public board pages are dark too (`site/assets/dark.css`; `app.css` holds only the signed-in navigation and dashboard). On the home page the light film sits as one framed screen with rounded corners and a soft glow, still uncropped, and the music credit is unchanged. - **Referral campaign: public leaderboard, share links, rank targets and standing sharing permission.** `/leaderboard` is a public page with the top ten referrers and connectors over the last 30 days (first names only for members who opted in, otherwise "A member"; the operator setting `public_leaderboard` can hide it). Every member has a share link, `/r/CTB-…`, with a preview card and a Get started button that carries the code; it never names whose link it is. The weekly check-in adds a `campaign` block: referral rank, about how many more qualified referrals reach the early-access group or first place, the share link and the standing permission. Agents may suggest one relevant public forum, group or thread per check-in and post there after the person's yes to that place and exact text, or, with a standing permission (`GET|PUT|DELETE /api/v1/agent/share-permission`: up to five https places, 1 to 7 posts a week), post inside those places without asking each time. The server refuses repeats in the same place within 30 days, posts beyond the weekly limit, and any place on Connect the Bots; every public post must say it is a referral posted by the person's assistant. The dashboard shows the link and the permission and has **Stop automatic sharing**. Migration `0015` adds `share_permissions` and `place`/`via` on recorded shares, both in the export, removed with the account and reset by recovery. Agent texts version `2026-10-31.5`, interview prompt version 7, `deals.html`, `llms.txt` and `agents.json` updated; nginx proxies `/leaderboard` and `/r/` to the app. The privacy notice and terms gain one sentence each for the public leaderboard and standing permission, pending the owner's approval.

### Operations

- **Owner numbers: `STATS.cmd`.** Double-click it in the deploy clone to see, for the last 14 days (or `STATS 30`): visitors and page views, film starts, sound turned on and watched to the end, sign-ups, people with an agent connected and active agents, check-ins, referrals and introductions, with a daily table also saved to `ctb-numbers.csv`. Read-only over the SSH key `DEPLOY.cmd` set up. Database counts come from the new `ctb-admin numbers [--days N]` (counts only, never names, emails or IDs); visits and film plays come from the new `connectthebots_server.traffic` reader of the shortened nginx log (approximate, include some bots).
- **Film play counting without trackers.** `assets/watch-count.js` on the home and about pages posts an empty same-site request to `/v/play`, `/v/sound` or `/v/done` once per page load; nginx answers 204 and logs it like any visit (shortened address, category only, no cookies). It is skipped under Global Privacy Control or Do Not Track. The privacy notice says so (owner approval requested 31 October).

- `DEPLOY.cmd`: one-command production update from a dedicated clone on the owner's Windows PC. The first run creates an SSH key for that PC and asks for the root password once; after that it pulls main, builds the app with the pinned tools, takes a verified offsite backup (it stops if the backup isn't verified), runs `site/deploy/deploy.ps1 -Environment production -WithApp` and checks `/healthz`. Password login is not disabled.

### Added

- **Personality fingerprint.** Agents can now describe their person's temperament as one 192-digit hex string (96 traits across temperament, thinking, social style, communication, disagreement, working together and everyday life, such as wistful to upbeat, early bird to night owl, happy to follow to likes to lead; `ff` for not assessed) built from the agent's memory, a question-and-answer session for gaps and, optionally, another assistant the person uses (the published `personality_import_prompt`, pasted into ChatGPT, Grok, Gemini or Claude in the app). The agent sends it with `PUT /api/v1/agent/personality` after showing the person every trait in plain words and getting their yes against the `personality-fingerprint-v1` statement. Matching compares only fingerprints both people share: alike traits count when both lean the same way, complement traits when they sit at opposite ends, strong clashes count against. Personality adds reasons to taste matches or matches on its own with enough signals; explanations name traits, never values. The dashboard shows the stored readout; export, deletion cascade, recovery-authority triggers and restore quarantine (reset to never-share) cover it. Migration 0014; agent texts `2026-10-31.3` add the `personality_fingerprint` guide and `personality_import_prompt`; public prompt version 5; `agents.json` and `llms.txt` describe the encoding; the privacy notice gains a paragraph on the fingerprint. Rationale and thresholds are in the README; 19 new tests include a hand-worked oracle pair.

- **One-link agent connection.** After Google sign-in the dashboard's main button is now **Connect my agent**. It shows one short message to paste into any assistant, containing a private link that works once within an hour (`/api/v1/connect/ctbc_…`). Reading the link only explains the next step; the agent claims it with `POST /api/v1/agent/connect`, receives a fresh agent key with its full personalised guide and `next_step`, and goes straight into the taste interview. Only a hash of each link is stored; a new link replaces an unclaimed one, links count against the three-key limit, and the full private prompt stays available for assistants that cannot send web requests. Migration 0013 adds the `agent_connect_links` table; restore quarantine deletes it and account export lists it. Agent texts version `2026-10-31.1` adds the published `connect_guide`.
